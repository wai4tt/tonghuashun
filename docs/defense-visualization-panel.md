# 答辩说明：投资分析“过程 + 结论”的可视化面板

> 这一篇是答辩口径，可以直接照着讲。最后一节是 3 分钟演示脚本，前面是机制与追问。
> 对应代码：`frontend/insight_panel.py`（面板）、`frontend/result_views.py`（挂载点）、
> `backend/app/main.py`（阶段计时与审计字段）、`backend/app/services/research_report.py`
> （结构化报告）。对应文档：`docs/trend-and-decision.md`。

## 0. 一句话结论（30 秒版）

我们没有把“可视化面板”做成前端自己算出来的效果图，而是让后端在分析过程中把
**每个阶段耗时、每次取数、每个任务节点、每个智能体的规则分与模型分、每条风险与
核验问题**都记录进同一次响应，前端只负责把这些审计字段画出来。因此面板上看到的
每一个数字，都能在同一条 API 响应里找到同名字段；面板关掉、页面关掉，数据仍在
响应和历史记录里。这就是“过程可视化 + 结论可视化”的机制。

## 1. 面板在哪里、怎么打开

1. 登录后进入「投资问答」，选择研究方向（个股研究 / 行业分析 / 市场解读 / 基金筛选 / 可转债分析）。
2. 输入问题，等待分析完成（深度思考模式会在线补查并完成核验）。
3. 回答下方有一个可展开的 **「分析过程与结论可视化面板」**，里面两个页签：
   - **分析过程**：阶段耗时条形图、取数与补证统计、任务节点表、模型调用明细；
   - **结论可视化**：合规状态、综合置信度进度条、分项评分对比图、资料来源分布、
     风险清单、交叉核验发现。
4. 同一屏下方还有 **结构化投资分析报告**（结论 / 关键信息 / 数据覆盖 / 分维度证据），
   可下载 Markdown；PDF 导出保留原有入口。

## 2. 面板展示什么（字段与来源一一对应）

| 面板元素 | 展示内容 | 来源字段（同一条分析响应） | 产生位置 |
| --- | --- | --- | --- |
| 阶段耗时条形图 | 核对偏好、理解问题、自动取数、专业研判、事实核验、合规审核、保存对话各自的毫秒数 | `timings_ms` | `main._analyze_portfolio` 的 `report(stage)` 计时 |
| 关键指标卡 | 完整分析耗时、参与核验资料数、实际引用数、模型调用次数 | `timings_ms.total`、`facts`、`evidence`、`model_calls` | 协调器与 API 汇总 |
| 取数与补证 | 计划/成功/沿用/失败的能力清单、补证轮数、失败原因 | `data_acquisition.requested_capabilities` 等 | `services/research.py`、`research_recovery.py` |
| 任务节点表 | 每个节点的智能体、状态、依赖、超时 | `task_plan.nodes` | `CoordinatorAgent.plan` |
| 模型调用明细 | 用途、模型名、状态、输入字符、耗时 | `model_calls[]` | `agents/llm_agents.py` 的调用记录 |
| 合规状态 / 置信度 | PASS / REVIEW / BLOCK，以及 0–100% 置信度 | `compliance.status`、`confidence` | 合规闸门与聚合器 |
| 分项评分 | 每个专业智能体的规则分与模型分 | `agent_results[].rule_score / model_score` | `services/rule_agents.py` 先算规则分，模型只解释 |

## 3. 机制：为什么是“过程可视化”，不是“结果包装”

一次分析在服务端是流水线，不是一次函数调用：

1. **阶段计时**：入口用 `perf_counter()` 记录每个真实阶段的开始与结束，阶段名直接
   来自处理流程（例如“自动取数”“事实核验”“合规审核”），并行阶段按实际等待时间
   累计。前端不做任何时间估算。
2. **取数审计**：每一次问财只读能力调用都登记为请求/成功/沿用/失败/空结果，补证
   轮次与耗时单独记录。面板把这份审计画成能力清单与统计，用户能看出“哪些资料是
   实时取的、哪些是沿用的、哪些没取到”。
3. **任务 DAG**：主协调智能体先生成任务节点（含依赖、超时、优先级），调度器回写
   状态；面板直接渲染 `task_plan.nodes`，所以看到的是真实执行计划，不是示意流程。
4. **双评分**：专业节点先由确定性规则算出 `rule_score`，模型只负责解释；模型返回
   空分时沿用规则分。面板同时画两条柱，评委会看到“规则分可复算、模型分只作对照”。
5. **闸门**：事实核验 → 交叉验证 → 合规审核的真实状态进入 `compliance`、
   `cross_validation`；面板把状态、问题、风险原样展示，不因为界面好看而隐藏 REVIEW。

一句话：**面板是审计日志的可视化，不是二次创作。**

## 4. 为什么可信（三个可验证点）

- **可复算**：规则分、置信度聚合、走势判断都有固定公式（见
  `docs/trend-and-decision.md` 的信号与权重表），同一输入重复运行结果一致。
- **可追溯**：每个数字都能在响应 JSON 里找到同名字段；每条证据都有 `fact_id`，
  Markdown 导出里保留来源与期间。
- **缺失显式**：没有数据的维度显示“未覆盖 / 未取得”，不补 0、不插值、不用
  “大概”“可能”填空；资料冲突时相关指标会被撤下并提示复核。

## 5. 如果评委说“前端看不出来 / 演示环境没有数据源”

这三层兜底按顺序说：

1. **面板本身是数据驱动的**：没有数据源时，面板不会伪造过程，而是显示“本次响应
   没有阶段耗时记录（可能来自历史精简记录）”或“取数状态：unavailable”。这本身
   就是机制在起作用——它宁可承认没有，也不画假图。
2. **同一份数据可以脱离前端看**：打开 `http://127.0.0.1:8000/docs` 调
   `POST /api/v1/portfolio/analyze`，响应里的 `timings_ms`、`data_acquisition`、
   `task_plan`、`agent_results`、`compliance` 就是面板的全部数据源；也可以直接
   下载 Markdown 报告或导出 PDF，过程与结论同样完整。
3. **历史记录可回放**：分析结果落库后，从「历史记录 → 分析详情」重新打开，
   面板用同一份历史 payload 重绘，说明可视化不依赖“当次页面会话”。

## 6. 可能追问与回答

**Q1：这些图是不是前端算出来的？换个前端是不是就没了？**
A：不是。阶段耗时、取数统计、任务节点、评分、风险全部由后端写入响应；前端只做
映射。换 React 或直接读 JSON 都能得到同样的面板内容，这也是我们把面板放在
`frontend/insight_panel.py`、把口径写在后端服务的原因。

**Q2：为什么不做实时动画式的“智能体思考过程”？**
A：流式阶段是真的（`/portfolio/analyze/stream` 逐阶段推送），但我们不把
“模型正在思考”这类不可验证的内容画成动画。可视化只呈现可审计事实，避免用
表演替代证据。

**Q3：置信度怎么来的？会不会是拍脑袋？**
A：置信度由证据完整度、专业节点一致性、核验与合规状态聚合，失败或证据不足会
拉低而不是抬高；面板把它的构成（资料数、引用数、风险数、核验问题）同时列出，
评委可以对着数字核对。它不表示上涨概率。

**Q4：走势判断和投资结论是什么关系？会不会互相矛盾？**
A：两者刻意分层。走势判断只用历史收盘价做描述性观察（MA5、三日升幅、信号中和），
不进入投资建议的证据链与合规审核；投资结论只基于已核验的事实。面板会明确标注
“走势判断是描述性观察，不进入证据链”，所以即使技术面偏强、基本面证据不足，
结论仍是“待复核”，不会互相冒充。

**Q5：为什么有的回答面板是空的？**
A：两种正常情况：一是精简/3 秒模式没有在线取数与模型调用，`timings_ms` 和
`model_calls` 本来就应该少；二是历史记录保存的是轻量摘要。面板会写明原因，
不把“没有”伪装成“有”。深度思考模式下的完整分析会显示全部阶段。

**Q6：这么多指标，用户看得懂吗？**
A：默认只显示 4 张关键卡和两张图，明细都在展开区；每个图下面有一句“怎么读”，
信号拆解里每个信号都带读数和解释。信息密度是可展开的，不是一次性糊在屏幕上。

**Q7：和市面上“AI 炒股软件”的看板有什么区别？**
A：区别在数据来源和边界。我们的每个数字都有来源、期间和 `fact_id`；没有数据的
地方明确显示缺失；最终结论过事实核验、交叉验证、合规三道闸门；面板展示的是
审计记录，而不是美化后的收益曲线。

**Q8：为什么自选对比能给“哪个更有投资价值”的结论？依据是什么？**
A：只在同类型、同口径、至少覆盖估值/成长/质量中两项时才给排序；得分 = 组内
相对档位 50% + 绝对区间 50%，权重固定、公式公开；负 PE 不当作便宜，缺失维度
整体退出。结论同时给出优势、不足、与第二名的分差，并声明不构成买入建议。

## 7. 3 分钟演示脚本

1. **（20 秒）** 打开「投资问答」，说明默认“3 秒研究”只用已加载资料，需要在线取数
   和完整核验时切“深度思考”。
2. **（60 秒）** 提问“分析一下贵州茅台的估值和主要风险”，等待完成后展开
   「分析过程与结论可视化面板」：先点“分析过程”，指阶段耗时条、取数能力清单、
   任务节点表——说明这些是服务端真实记录。
3. **（40 秒）** 切到“结论可视化”：合规状态、置信度、规则分/模型分对比、来源分布、
   风险清单；指出 REVIEW 时系统会明确提示“请勿直接据此买卖”。
4. **（30 秒）** 下滑到结构化投资分析报告：关键信息、数据覆盖、未覆盖维度，
   点“下载 Markdown”，打开展示结论与来源都在。
5. **（20 秒）** 打开「市场解读」页：六大指数卡片（MA5 / 3 日累计 / 判断）+ 归一化
   走势对比 + 单指数信号拆解；说明走势不进入证据链。
6. **（10 秒）** 收尾：一句话总结“过程可审计、结论可追溯、边界可解释”。

## 8. 如果只允许用一句话回答“这个机制是什么”

> 后端把分析过程写成可审计的时间线、取数清单、任务 DAG 与双评分，前端只把这些
> 字段画成两页签面板；结论页展示的是过完事实核验、交叉验证和合规闸门的结果，
> 所以面板既不是装饰，也不是预测，而是这套研究流程的“行车记录仪”。
